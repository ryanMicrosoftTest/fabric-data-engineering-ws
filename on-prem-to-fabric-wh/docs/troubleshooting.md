# Troubleshooting

Symptom-→-cause-→-fix for the failures most likely to come up when running this POC. If you hit something not listed, capture the **exact** error text (especially anything in quotes after `Login failed for user`) and the **audience** you used to acquire the token before debugging further.

| Symptom | Likely cause | Fix |
|---|---|---|
| `Login failed for user '' (18456)` (bare empty principal) | Connection string is using `Authentication=ActiveDirectoryServicePrincipal` with `UID`/`PWD`, or the access token was acquired against the wrong audience (e.g., `api.fabric.microsoft.com`) so the server treats the request as anonymous. | Switch to token injection per [`auth-pattern-explained.md`](./auth-pattern-explained.md). Confirm the audience is exactly `https://database.windows.net/.default`. Remove `Authentication=`, `UID=`, and `PWD=` from the connection string. |
| `Login failed for user '<spn-app-id>'` (SPN GUID is named) | Token reached the server and the SPN was identified, but the SPN lacks a database role inside the Warehouse. | In a SQL editor connected as a Warehouse admin, grant `db_datareader` + `db_datawriter` (or schema-scoped `GRANT SELECT, INSERT, UPDATE, DELETE`) to the SPN. Re-check workspace + Warehouse-item membership too. |
| `Cannot open database "<name>" requested by the login. The login failed.` | `DATABASE=` is wrong (a GUID, the workspace name, or the FQDN host portion) — or the SPN does not have access to *this specific* Warehouse item even though it's in the workspace. | Verify `WH_DATABASE` in `.env` is the Warehouse item **name** as shown in the Fabric portal title bar (not a GUID). Then confirm the SPN is added to that Warehouse item's permissions, not just to the workspace. |
| `Data source name not found and no default driver specified` / SQLSTATE `IM002` | ODBC Driver 18 for SQL Server is not installed (or only an older driver is installed). | Install [ODBC Driver 18 for SQL Server](https://learn.microsoft.com/sql/connect/odbc/download-odbc-driver-for-sql-server). On Windows, confirm in *ODBC Data Sources (64-bit) → Drivers*. Re-run. |
| `pyodbc.OperationalError: ('08001', ...)` / `TCP Provider: No connection could be made because the target machine actively refused it` | Outbound port 1433 to `*.datawarehouse.fabric.microsoft.com` is blocked by a firewall, VPN, or proxy. | Open outbound 1433 to that hostname; test with `Test-NetConnection <fqdn> -Port 1433` (PowerShell) or `nc -zv <fqdn> 1433`. Coordinate with network team if needed. |
| `azure.core.exceptions.ClientAuthenticationError` from `azure-identity` (raised by `ClientSecretCredential.get_token`) | Wrong tenant ID, wrong SPN client ID, or the SPN's client secret has expired / been rotated. | Verify `TENANT_ID` and `SPN_CLIENT_ID` in `.env`. Rotate the SPN secret in Entra → *App registrations → Certificates & secrets*, store the new value in Key Vault under the same `KV_SECRET_NAME`, retry. |
| `azure.core.exceptions.HttpResponseError: (Forbidden)` from Key Vault when calling `get_secret` | The laptop user (the identity backing `DefaultAzureCredential`) does not have `Key Vault Secrets User` on the vault. | Azure Portal → vault → *Access control (IAM)* → *Add role assignment* → *Key Vault Secrets User* → assign to the laptop user. Run `az logout && az login` to refresh the token, retry. |
| `azure.keyvault.secrets.exceptions.KeyVaultError: SecretNotFound` (or `ResourceNotFoundError`) | `KV_SECRET_NAME` in `.env` does not match the actual secret name in the vault (typo, wrong case, or wrong vault). | Azure Portal → vault → *Secrets* → confirm the secret name and that `KV_NAME` points to the same vault. Update `.env`, retry. |
| `[Microsoft][ODBC Driver 18 for SQL Server]MultipleActiveResultSets is not supported` (or similar MARS error) | The connection string has `MultipleActiveResultSets=true` (or `MARS_Connection=yes`). Fabric Warehouse does not support MARS. | Remove the `MultipleActiveResultSets` / `MARS_Connection` keyword from the connection string. If the calling library adds it by default (some SQLAlchemy dialects do), set it explicitly to `false`. |
